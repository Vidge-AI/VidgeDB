# VidgeDB JSON-RPC Reference

Complete reference for the `vidgedb --service <db.vdg>` wire protocol. **Every request/response pair below was generated by executing the release binary** (`vidgedb 0.1.0`, 2026-09-29 session) — nothing copied from an older report.

See also: [README.md](README.md) (user guide), [vidgeql-reference.md](vidgeql-reference.md), [deployment.md](deployment.md).

---

## 1. Protocol

- **Transport**: stdio of the `vidgedb --service` child process. One JSON-RPC 2.0 request per line on stdin, one response per line on stdout. (Deliberately not Content-Length framed — trivially parseable from every language, including shell.)
- Service invocation:

```bash
vidgedb --service /data/plant.vdg [--agent-id diag-agent] [--role reader|writer|ingest] [--retention-days N]
```

- **Requests**: `{"jsonrpc":"2.0","id":<number|string>,"method":"<name>","params":{...}}`.
- `params` may be a JSON **object** (named), an **array** (positional, order documented per method), or absent where every param is optional.
- **Notifications** (request with no `id`): executed, **no response line** (JSON-RPC 2.0); a note goes to stderr: `vidgedb: notification "log_event" handled (no response per JSON-RPC)`.
- **Responses**: success → `{"id":…,"jsonrpc":"2.0","result":{…}}` (keys alphabetical on the wire — serde's map ordering; parsers must not care). Failure → `{"id":…,"jsonrpc":"2.0","error":{"code":<n>,"message":"…"}}`.
- **Two error shapes**:
  - Transport/protocol failures → the JSON-RPC `error` member with codes `-32700, -32600, -32601, -32602, -32000, -32003` (table below).
  - Method-level *semantic* problems ("unknown entity 'X'") → HTTP-equivalent of an application error: a normal `result` whose value is exactly `{"error": "…"}`. SDKs map these to exceptions with code 0.
- **Robustness contract**: zero panic on any input; after a `-32700` the service keeps listening (verified — a malformed line later in a session did not kill the stream).
- Logging: all service notes (retention passes, notifications, request count) go to **stderr**; stdout is reserved for the protocol.

### Error codes

| Code | Meaning | Raised by |
|---|---|---|
| `-32700` | Parse error — line is not valid JSON | transport |
| `-32600` | Invalid request — not a request object / missing `method` string | transport |
| `-32601` | Method not found | unknown method name |
| `-32602` | Invalid params | missing/bad-typed param, empty `points`, non-integer `ts`, `key` not u32 |
| `-32000` | Storage error | engine-level failure surfaced by the method |
| `-32003` | **Write forbidden** — server-defined | a write method on a `--role reader` service; refusal is also audited |

Real samples (all captured; the stream survived each one):

```json
{"error":{"code":-32602,"message":"\"points\": must be a non-empty array of [timestamp, value] pairs"},"id":1,"jsonrpc":"2.0"}
{"error":{"code":-32602,"message":"points: ts must be an integer, value must be a number (pair form [ts, value])"},"id":2,"jsonrpc":"2.0"}
{"error":{"code":-32601,"message":"unknown method \"nope\""},"id":17,"jsonrpc":"2.0"}
{"error":{"code":-32700,"message":"parse error: expected ident at line 1 column 2"},"id":null,"jsonrpc":"2.0"}
{"error":{"code":-32003,"message":"write forbidden (-32003): agent 'must-stay-reader' holds role Reader; telemetry/topology ingestion requires opening the API with Role::Writer or Role::Ingest (spec §55 derrogation, Phase 11). The attempt is recorded in the audit trail."},"id":1,"jsonrpc":"2.0"}
```

## 2. Method reference

Roles: **R** = any role · **W** = `--role writer|ingest` only (a Reader gets `-32003`).

### schema — `R`

Inventory of what the agent can query (entity types, relation topologies, series names, provenance classes).

```json
→ {"jsonrpc":"2.0","id":1,"method":"schema"}
← {"id":1,"jsonrpc":"2.0","result":{
     "entity_types":["Drive","Motor","PLC","Pump"],
     "provenance_classes":["Fact","Observation","Specification","Inference","Hypothesis","Event","Command","Configuration"],
     "relation_topologies":["electrical","mechanical","network"],
     "series":["Motor42.current"]}}
```

Errors: `-32000` storage. Audited with an empty summary.

### list_entities — `R`

Enumerate entities **without knowing them in advance** — the inventory call. Aliased as `entities` (same handler, both names accepted).

Before this existed the only path was `MATCH (x:Type) RETURN x`, which requires already knowing the type; `MATCH (x) RETURN x` with no type returns 0 rows. That made an inventory impossible in one call and left a graph editor unable to populate its node list without guessing names.

| param | type | default | notes |
|---|---|---|---|
| `type` | string | *(none)* | restrict to one entity type |
| `limit` | integer | `0` | max rows; **`0` = no cap**. Negative → `-32602` (a negative would cast to a huge `usize`, i.e. silently "no cap" while looking like a cap) |

```json
→ {"jsonrpc":"2.0","id":4,"method":"list_entities","params":{"type":"Motor"}}
← {"id":4,"jsonrpc":"2.0","result":{
     "entities":[{"key":1,"name":"EMOT01","type":"Motor"}],
     "total":1,            ← matching rows
     "entities_in_db":2,   ← total cells in the store
     "truncated":false}}   ← true when `limit` cut the reply
```

`total` and `truncated` are always present so a truncated page is never mistaken for the complete set. Errors: `-32000` storage, `-32602` bad `limit`.

### graph — `R`

The **whole graph in one round-trip**: what a graph editor draws. Without it, rendering N nodes costs one `get_entity` per node plus one call per relation (O(N+E) round-trips).

| param | type | default | notes |
|---|---|---|---|
| `limit` | integer | `0` | max **relations**; `0` = no cap. Entities are always returned in full |

```json
→ {"jsonrpc":"2.0","id":5,"method":"graph"}
← {"id":5,"jsonrpc":"2.0","result":{
     "entities":[{"key":0,"name":"PLANT01","type":"Plant"},
                 {"key":1,"name":"EMOT01","type":"Motor"}],
     "relations":[{"from":"EMOT01","to":"PLANT01",
                   "relation_type":"mechanical:feeds",
                   "valid_from":0,"valid_to":-1,
                   "provenance":"Observation"}],
     "relations_total":1,
     "truncated":false}}
```

Endpoints are given by **name**, not internal key: a client must not have to resolve keys one by one to draw an edge. `valid_to == -1` means open-ended. Only **live** relations are returned — deleted records are tombstones, never physically removed, and are filtered out. A relation whose endpoint no longer resolves appears as `<key:N>`. Errors: `-32000` storage.

### diagnose — `R`

The **8-step pipeline of spec §26** over one entity's window, as JSON. Strictly read-only: no store is mutated, and the step-8 hypotheses are **never persisted** (spec §29) — they are marked `"provenance": "Hypothesis"` in the reply.

This is the call that makes the engine usable from Python/JS/Go: the pipeline previously existed only as a Rust library function, so any platform wanting it would have had to be written in Rust.

| param | type | default | notes |
|---|---|---|---|
| `entity` | string, required | — | entity name |
| `from` / `to` | i64 | `0` / `i64::MAX/2` | window, inclusive |

```json
→ {"jsonrpc":"2.0","id":6,"method":"diagnose","params":{"entity":"EMOT01","from":1699999000,"to":1700005000}}
← {"id":6,"jsonrpc":"2.0","result":{
     "entity":"EMOT01",
     "window":{"from":1699999000,"to":1700005000},
     "component":{"key":1,"name":"EMOT01","type_name":"Motor","props":[{"name":"spec.current.max","value":"10"}],"provenance":"Observed"},
     "dependencies":{"upstream":[],"downstream":[]},
     "topology":[],
     "events":[], "events_note":"v0 limitation: no event store exists yet …",
     "measurements":[{"series":"EMOT01.current","signal":"current","points":2,"min":8.0,"max":12.5,"provenance":"Observed"}],
     "checks":[{"entity":"EMOT01","signal":"current","status":"VIOLATION","observed":12.5,
                "expected_max":10.0,"expected_prov":"Specification","observed_prov":"Observation",
                "deviation":2.5,"points_checked":2,"unit":null}],
     "anomalies":[{"entity":"EMOT01","signal":"current","observed":12.5,"expected_max":10.0,"deviation":2.5,"points_checked":2,"provenance":"observed"}],
     "causal_paths":[{"signal":"current","hypothesis":"signal current exceeded expected max over window …","confidence":0.5,"provenance":"Hypothesis","source":"vidgedb_diagnose_v0","upstream":[]}],
     "provenance_note":"provenance preserved: component/dependencies/…"}}
```

`expected_prov` vs `observed_prov` is the point of the report: a violation compares a **Specification** against an **Observation**, and the consumer can see which side is which.

An **unknown entity is not an error**: `component` is `null`, `entity` echoes the requested name, and every list is empty. A caller renders "component not found" instead of breaking its page. Errors: `-32000` storage.

### query — `R`

Execute core VidgeQL (`MATCH`/`WHERE`/`AT`/`RETURN`/`LIMIT`). VQL parse/execution problems are **not** transport errors — they land in `result.error`.

| param | type | notes |
|---|---|---|
| `vql` | string, required | the query |

```json
→ {"jsonrpc":"2.0","id":2,"method":"query","params":{"vql":"MATCH (m:Motor) -[:ELECTRICAL]-> (d:Drive) RETURN m, d"}}
← {"id":2,"jsonrpc":"2.0","result":{"n":1,"rows":[
     {"d":{"key":1,"name":"Drive12","properties":{"vendor":"ABB"},"type":"Drive"},
      "m":{"key":2,"name":"Motor42","properties":{"spec.current.max":"10","vendor":"ABB"},"type":"Motor"}}]}}
```

Possible outcomes: `rows`/`n`; or `{"error":"parse error: …"}` (e.g. `"MATCH (m:Motor) RETURN m LIMIT"` → `"parse error: unexpected token: expected number"`); `-32602` if `vql` missing; `-32000` storage.

### query_temporal — `R`

Temporal VidgeQL with `MEASURE … DURING …` and aggregate RETURN items.

| param | type | notes |
|---|---|---|
| `vql` | string | may include `MEASURE var.signal DURING last(nH)\|t1..t2` |
| `now` | i64, optional | anchors `last(...)` windows; **defaults to the current unix time** |

```json
→ {"jsonrpc":"2.0","id":20,"method":"query_temporal","params":
    {"vql":"MATCH (m:Motor) WHERE m.name = \"Motor42\" MEASURE m.current DURING 1759999000..1760003600 RETURN max(m.current), min(m.current), avg(m.current), count(m.current)","now":1760003600}}
← {"id":20,"jsonrpc":"2.0","result":{"n":1,"rows":[
    {"avg":{"kind":"Avg","value":9.683333333333332},
     "count":{"kind":"Count","value":6.0},
     "m":{"key":2,"name":"Motor42","properties":{"spec.current.max":"10","vendor":"ABB"},"type":"Motor"},
     "max":{"kind":"Max","value":11.7},"min":{"kind":"Min","value":8.2}}]}}
```

Notes (verified): an entity with no series in the window still returns its row with `value: null` aggregates and `count 0`; an aggregate whose target series does not exist for that entity yields an aggregate with `value: null`. Errors: `{"error":"parse error: DURING expects last(n) or a..b"}`; wrong RETURN field sets on `MEASURE`-less queries simply return variables.

### get_entity — `R`

Full entity card by stable numeric key.

| param | type | notes |
|---|---|---|
| `key` | u32 **or integer-valued string** | `{"key": 2}` and `{"key": "2"}` both accepted |

```json
→ {"jsonrpc":"2.0","id":24,"method":"get_entity","params":{"key":2}}
← {"id":24,"jsonrpc":"2.0","result":{
    "key":2,"name":"Motor42","type":"Motor",
    "properties":{"spec.current.max":"10","vendor":"ABB"},
    "relations_in":[{"from":"Pump17","provenance":"Fact","relation_idx":2,
                     "topology":"mechanical","type":"coupled_to","valid_from":0,"valid_to":-1}],
    "relations_out":[{"provenance":"Fact","relation_idx":1,"to":"Drive12",
                      "topology":"electrical","type":"fed_by","valid_from":0,"valid_to":-1}]}}
```

Errors: semantic `{"error":"unknown entity key 42"}`; `-32602` `"\"key\": must be an unsigned integer, got \"Motor42\""`; `-32602` on missing `key`.

### get_measurements — `R`

Raw points of series `<entity>.<signal>` in the **inclusive** `[from, to]` unix-seconds window, plus count/min/max (null when the window is empty).

| param | type | default |
|---|---|---|
| `entity` | string | required |
| `signal` | string | required |
| `from` | i64 | `0` |
| `to` | i64 | `i64::MAX/2` |

```json
→ {"jsonrpc":"2.0","id":21,"method":"get_measurements","params":{"entity":"Motor42","signal":"current","from":1760000000,"to":1760001200}}
← {"id":21,"jsonrpc":"2.0","result":{"count":3,"max":11.7,"min":8.2,
    "points":[{"t":1760000000,"value":8.2},{"t":1760000600,"value":9.1},{"t":1760001200,"value":11.7}]}}
```

Errors: semantic `{"error":"no series named 'Nope404.current'"}`; `-32602` missing `entity`/`signal`.

### check — `R`

Spec-§25 deviation engine: expected from the entity property `spec.<signal>.max` (+optional `spec.<signal>.unit`), observed = **max of the window** (worst case), deviation = observed − expected.

| param | type | default |
|---|---|---|
| `entity` | string | required |
| `signal` | string | required |
| `from` / `to` | i64 | `0` / `i64::MAX/2` |

```json
→ {"jsonrpc":"2.0","id":22,"method":"check","params":{"entity":"Motor42","signal":"current","from":1760000000,"to":1760003600}}
← {"id":22,"jsonrpc":"2.0","result":{
    "deviation":1.6999999999999993,"entity":"Motor42","expected_max":10.0,
    "expected_provenance":"Specification","observed":11.7,
    "observed_provenance":"Observation","points_checked":6,"signal":"current",
    "status":"VIOLATION","unit":null,"window":{"from":1760000000,"to":1760003600}}}
```

Statuses & semantics: `OK` (observed ≤ spec, strict — equality is OK), `VIOLATION` (observed max > spec), `NO_DATA` (spec present, window empty, including missing series), `NO_SPEC` (no spec prop — verified: `{"status":"NO_SPEC","expected_max":null,…,"points_checked":0}`). Unknown entity → semantic `{"error":"unknown entity 'Nope404'"}`.

### trace — `R`

BFS path between two named entities, **out-edges only**, all topologies, deterministic order.

| param | type | default |
|---|---|---|
| `from`, `to` | string | entity **names** |
| `max_hops` | i64 | 6 (clamped 0..255) |

```json
→ {"jsonrpc":"2.0","id":4,"method":"trace","params":{"from":"Pump17","to":"Drive12","max_hops":6}}
← {"id":4,"jsonrpc":"2.0","result":{"found":true,"n_hops":2,
    "path":[{"key":3,"name":"Pump17","properties":{},"type":"Pump"},
            {"key":2,"name":"Motor42",…},
            {"key":1,"name":"Drive12",…}],
    "steps":[{"from":"Pump17","provenance":"Fact","relation_idx":2,
              "relation_type":"coupled_to","to":"Motor42","topology":"mechanical"},
             {"from":"Motor42","provenance":"Fact","relation_idx":1,
              "relation_type":"fed_by","to":"Drive12","topology":"electrical"}]}}
```

Unreachable → `{"found":false,"path":[],"steps":[]}`; unknown name → semantic `{"error":"unknown entity 'Ghost'"}`.

### provenance — `R`

Provenance explainer + the provenance byte of every live relation (role-dependent note text).

```json
→ {"jsonrpc":"2.0","id":28,"method":"provenance"}
← {"id":28,"jsonrpc":"2.0","result":{
    "note":"Provenance classes: Fact=0 (structural ground truth), Observation=1 (…), Specification=2 (…), Inference=3 (…), Hypothesis=4 (…), Event=5, Command=6, Configuration=7. The engine never promotes Hypothesis to Fact/Observation; this agent holds the Reader role (spec §55): every write is refused and audited…",
    "provenance_classes":["Fact","Observation","Specification","Inference","Hypothesis","Event","Command","Configuration"],
    "relations":[{"dst":"Drive12","provenance":"Fact","provenance_byte":0,"relation_idx":1,
                  "src":"Motor42","topology":"electrical","type":"fed_by","valid_from":0,"valid_to":-1}]}}
```

A Writer/Ingest gets the same shape with a note describing the Phase-11 derrogation (ingests as Fact/Observation only).

### get_state — `R`

Value of one state key valid at `at` (default now). Unknown pair → `result: null` (not an error).

```json
→ {"jsonrpc":"2.0","id":25,"method":"get_state","params":{"entity":"Motor42","key":"running"}}
← {"id":25,"jsonrpc":"2.0","result":{"valid_from":1760000000,"value":"yes"}}
```

### state_history — `R`

Every `[valid_from, valid_to)` pair for `(entity, key)`; `valid_to: -1` = open-ended. Unknown pair → `{"history":[],"n":0}`.

```json
→ {"jsonrpc":"2.0","id":26,"method":"state_history","params":{"entity":"Motor77","key":"running"}}
← {"id":26,"jsonrpc":"2.0","result":{"history":[
    {"valid_from":1760009500,"valid_to":1760009500,"value":"no"},
    {"valid_from":1760009500,"valid_to":1760009500,"value":"yes"},
    {"valid_from":1760009500,"valid_to":-1,"value":"no"}],"n":3}}
```

### get_events — `R`

Events in the inclusive `[from, to]` window (defaults `i64::MIN/2` .. `i64::MAX/2`), `entity` optional (null = all).

```json
→ {"jsonrpc":"2.0","id":27,"method":"get_events","params":{"entity":"Motor42","from":1760000000,"to":1760003600}}
← {"id":27,"jsonrpc":"2.0","result":{"events":[
    {"details":"threshold relay trip","entity":"Motor42","name":"OverheatAlarm",
     "provenance":"Observation","provenance_byte":1,"timestamp":1760001200},
    {"details":"bearing swap","entity":"Motor42","name":"MaintenanceDone",
     "provenance":"Command","provenance_byte":6,"timestamp":1760002000}],"n":2}}
```

Errors: `-32602` when `entity` is neither string nor null.

### audit — `R`

The in-memory audit trail of this service session (spec §56). Reading the trail is itself audited.

```json
→ {"jsonrpc":"2.0","id":16,"method":"audit"}
← {"id":16,"jsonrpc":"2.0","result":{"entries":[
    {"agent_id":"plc-bridge","method":"upsert_entity",
     "params_summary":"name=Motor42 type=Motor props=2 relations=1 source=plc","timestamp":1790702414},
    {"agent_id":"plc-bridge","method":"ingest_points",
     "params_summary":"entity=Motor77 signal=current n=1000","timestamp":1790702414},
    …],"n":6}}
```

Refused writes are audited too: `"params_summary":"REFUSED (role=Reader, write forbidden -32003)"`.

### ingest_points — `W`

Batch-append telemetry into series `<entity>.<signal>` (auto-created on first write). **One transaction per call** — 10 000 points, one commit; the internal buffer auto-flushes a chunk every 256 points.

| param | type | notes |
|---|---|---|
| `entity` | string | series owner (its name prefixes the series) |
| `signal` | string | signal name |
| `points` | array | each item `[integer_ts, number_value]`, or `{"ts":…,"value":…}` / `{"timestamp":…,"value":…}` objects. **Must be non-empty.** Float `ts` or string `value` → `-32602`. |

**1000 points in one call** (executed; wall result):

```json
→ {"jsonrpc":"2.0","id":1,"method":"ingest_points","params":
    {"entity":"Motor77","signal":"current","points":[[1759999000,4.0],[1759999001,4.0],… 1000 pairs …]}}
← {"id":1,"jsonrpc":"2.0","result":{"accepted":1000,"chunks_flushed":4,"series_id":2}}
```

(ceil(1000/256) = 4 chunks; `series_id` is the internal index.) A 6-point batch on a fresh series → `{"accepted":6,"chunks_flushed":1,"series_id":0}`.

Errors: `-32602` for empty/non-wellformed points (never a silent no-op); on a Reader: `-32003` (audited).

### upsert_entity — `W`

Create or update an entity. Properties **merge** (a `null` value never erases an existing prop); relations are appended and **deduped** against live records; provenance of created relations comes from the declared `source`: `"plc"` ⇒ `Fact`, `"agent"`/`"sensor"` ⇒ `Observation`, anything else → semantic error. Unknown relation target → semantic error and **the whole transaction is rolled back** (nothing half-written).

| param | type | notes |
|---|---|---|
| `name` | string | non-empty |
| `type` | string | non-empty |
| `props` | object `{k: v\|null}` or array of `[k, v\|null]` | optional; values are strings |
| `relations` | array of `{to, relation_type: "topology:type", valid_from?}` | target must already exist; `valid_from` defaults 0 |
| `source` | `"plc"\|"agent"\|"sensor"` | default `"plc"` |

```json
→ {"jsonrpc":"2.0","id":3,"method":"upsert_entity","params":{
    "name":"Motor42","type":"Motor",
    "props":{"vendor":"ABB","spec.current.max":"10"},
    "relations":[{"to":"Drive12","relation_type":"electrical:fed_by"}],"source":"plc"}}
← {"id":3,"jsonrpc":"2.0","result":{"created":true,"key":2,"relations_added":1}}
// second identical call → {"created":false,"key":2,"relations_added":0}
```

Real semantic errors (captured): `{"error":"relation target 'Motor42' does not exist — create it first (an ingest agent never invents endpoints)"}`; `{"error":"merged properties exceed the inline cap (51 > 44 bytes) — drop props or store them as telemetry"}`; `{"error":"unknown source 'scada' (expected \"plc\" | \"agent\" | \"sensor\")"}`; `{"error":"name and type must be non-empty"}`; `{"error":"relation_type 'feeds' must be 'topology:type' (e.g. 'electrical:feeds')"}`; `{"error":"self-relations are not supported"}`.

### set_state — `W`

Write one state value; closes the prior open validity window, keeps history.

| param | type | notes |
|---|---|---|
| `entity`, `key`, `value` | string | required |
| `at` | i64 | optional; defaults to now |

```json
→ {"jsonrpc":"2.0","id":11,"method":"set_state","params":{"entity":"Motor42","key":"running","value":"yes","at":1760000000}}
← {"id":11,"jsonrpc":"2.0","result":{"entity":"Motor42","key":"running","set":true}}
```

### log_event — `W`

Append one occurrence.

| param | type | default |
|---|---|---|
| `name`, `entity` | string | required |
| `timestamp` | i64 | now |
| `provenance` | 0..7 | 1 (Observation) |
| `details` | string | `""` (only ~20 B kept — see limits) |

```json
→ {"jsonrpc":"2.0","id":12,"method":"log_event","params":
    {"name":"OverheatAlarm","entity":"Motor42","timestamp":1760001200,
     "provenance":1,"details":"threshold relay tripped"}}
← {"id":12,"jsonrpc":"2.0","result":{"entity":"Motor42","event":"OverheatAlarm","logged":true}}
```

Notifications work: the same call without `id` produces **no response** and a stderr note.

### retain — `W` (Writer/Ingest)

Drop **whole** time-series chunks strictly older than `before` (unix seconds; default now).

```json
→ {"jsonrpc":"2.0","id":3,"method":"retain","params":{"before":1760009000}}
← {"id":3,"jsonrpc":"2.0","result":{"chunks_removed":4,"points_removed":9}}
```

Nothing to remove → `{"chunks_removed":0,"points_removed":0}`. A Reader → `-32003`.

## 3. Ingestion cookbook

### 1000 points in 1 call

```bash
python3 - <<'EOF' > batch.jsonl
import json
points = [[1760000000 + i, 4.0 + (i % 5) * 0.5] for i in range(1000)]
print(json.dumps({"jsonrpc":"2.0","id":1,"method":"ingest_points",
                  "params":{"entity":"Motor77","signal":"current","points":points}}))
EOF
vidgedb --service batch.vdg --role writer < batch.jsonl
# {"id":1,"jsonrpc":"2.0","result":{"accepted":1000,"chunks_flushed":4,"series_id":0}}
```

Notes: one transaction → **one commit/fsync** for the whole batch (the WAL gets ~4 data-page frames + layout; that is why a big batch is not 4× slower than 256 pts); series `Motor77.current` auto-created with the write's provenance rules. Then aggregate:

```json
→ {"method":"query_temporal","params":{"vql":"MATCH (m:Motor) WHERE m.name = \"Motor77\" MEASURE m.current DURING 1759999000..1760010000 RETURN max(m.current), min(m.current), avg(m.current), count(m.current)","now":1760010000}}
← {"n":1,"rows":[{"avg":{"kind":"Avg","value":5.0},"count":{"kind":"Count","value":1000.0},
                 "m":{…},"max":{"kind":"Max","value":6.0},"min":{"kind":"Min","value":4.0}}]}
```

### Building a machine in 4 calls (topology, in dependency order)

```json
{"jsonrpc":"2.0","id":1,"method":"upsert_entity","params":{"name":"PLC01","type":"PLC","props":{"vendor":"Siemens"},"source":"plc"}}
{"jsonrpc":"2.0","id":2,"method":"upsert_entity","params":{"name":"Drive12","type":"Drive","props":{},"relations":[{"to":"PLC01","relation_type":"network:profinet"}],"source":"plc"}}
{"jsonrpc":"2.0","id":3,"method":"upsert_entity","params":{"name":"Motor42","type":"Motor","props":{"vendor":"ABB","spec.current.max":"10"},"relations":[{"to":"Drive12","relation_type":"electrical:fed_by"}],"source":"plc"}}
{"jsonrpc":"2.0","id":4,"method":"upsert_entity","params":{"name":"Pump17","type":"Pump","props":{},"relations":[{"to":"Motor42","relation_type":"mechanical:coupled_to"}],"source":"plc"}}
```

## 4. Wire notes for hand-rolled clients

- Flush after every line (`stdin.flush()`); read exactly one line per request.
- `id` may be a number or string; it is echoed verbatim. An `id: null` request is treated per JSON-RPC as a notification (no response).
- Responses always echo `"jsonrpc":"2.0"`.
- Keep a reader for **stderr** if you want the service's own notes (retention results, served-request counts) — they never pollute stdout.
- Sending EOF (close stdin) ends the service with exit code 0. SDKs use this for clean shutdown.
